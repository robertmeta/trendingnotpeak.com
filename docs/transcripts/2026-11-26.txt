Fork an experiment without restarting its tools

First up, TimeTravelContainer makes a running tool session something an agent can branch. Its rootless runtime clones processes, memory, files and network state using copy-on-write. Unchanged memory stays shared; changed pages consume additional space. Imagine an agent reaching an interesting point in a chip-design tool, then exploring two alternatives without loading the whole environment twice. Agent researchers could use TimeTravelContainer to fork running tool sessions and compare those branches. Across two electronic-design automation workflows, the authors report environment cloning eighty-four point one times faster, memory reductions of thirty-one to seventy-two percent, and complete agent runs one point seven to nine point four times faster. Those results concern the evaluated design tools. The paper describes support for Linux, Apple Silicon Macs and Windows through WSL two, without root privileges or hardware virtualization. A revealing next experiment would branch at the same checkpoint and inspect whether each copy preserves the state needed to continue independently.

Keep an agent's host awake while it works

Closer to the editor, Visual Studio Code one point one forty-eight addresses an extremely ordinary way for unattended agent work to stop: the computer falls asleep. A preview setting lets supported Agent Hosts prevent idle sleep during active turns, including after you close the window. The default applies while plugged in, and the hold ends shortly after the work finishes. Developers leaving a bounded task running get a useful control over the machine doing that work. The release also introduces experimental creation of isolated Linux Dev Containers without writing a container configuration, plus cleanup of inactive agent worktrees on remote hosts. Microsoft reports chat responses beginning thirty percent faster on average than in the previous stable release. That's response startup, rather than task completion. Start with a small task and check the host's behavior when the editor closes. The important machine may be the remote one, rather than the laptop in front of you.

Restore parallel drafting to feedback models

Turning inside the model, Feedback Shortcut tackles a dependency that makes speculative decoding awkward. Latent Feedback Transformers feed one position's final hidden state into the next position. That can improve prediction, but the next token now needs information that hasn't been computed yet. Feedback Shortcut learns a small projection that supplies a stand-in, allowing several drafted tokens to be checked together. During the next verification pass, it corrects the preceding drafts using newly available states, without another model call. At one hundred thirty-five million and seven hundred eighty million parameters, the authors report decoding two point four to two point eight times faster than exact latent-feedback decoding, with nearly matching text-prediction quality and about two percent extra training compute. Architecture researchers get a concrete way to investigate feedback without giving up parallel verification. Compare prediction quality and complete generation latency together, especially as batch size changes. The scheduling of a correction can matter as much as the correction itself.

Combine generated imagery with editable programs

For visual creation, NVIDIA's Nemotron-Labs-VisualCreation connects two useful representations: discrete tokens for raster images, and explicit programs for structured artifacts. A shared interface generates, renders and inspects the results. Its harness plans the work, selects image candidates and makes targeted repairs to editable structured or hybrid outputs. Creative-tool researchers could investigate a document that combines expressive imagery with a chart or layout that remains editable. The framework includes an image tokenizer, a raster generator and a family of structured-code models. With the same raster generator, the authors report their native harness raising one GenEval-two evaluation score from thirty-one point seven one to fifty-two point five six. That's evidence about the evaluated system, rather than a guarantee that every requested page becomes correct. An interesting test would change one chart label after generation and inspect whether the repair preserves the rest of the composition. Editability becomes tangible when a small correction stays small.

Give a Mac coding agent a specialized local engine

Meanwhile, on Apple Silicon, rustling is a Rust inference engine built specifically for Inkling two Mini. It exposes an OpenAI-compatible API, allowing tools such as Codex, aider and OpenCode to connect much as they would to a hosted model. Developers exploring an on-device assistant could use rustling to serve local coding models while studying a deliberately specialized runtime. Supporting one model family gives the project room to optimize around its details. The README describes generating whole tokens in one GPU submission, retaining processed prompts across requests and restarts, and copying token sequences repeated from the conversation. Those are implementation descriptions; there's no supported comparative speed result to promise here. Apple Silicon is required, and other platforms aren't supported. Begin with a small repository question, restart the engine, then repeat the request. Record startup behavior and check the answer as carefully as you check the wait.

Keep AI conversations in a searchable local folder

Away from model serving, Carry gives conversations a life outside their original chat interface. The browser extension describes automatically backing up chats, projects and files from ChatGPT, Claude, Gemini and Grok into a folder you choose. You can search the saved material and attach a transcript when continuing in another assistant. Developers who scatter design decisions across several services could use Carry to save chats as Markdown, then search those records with familiar tools. The useful distinction is that continuing means supplying a saved transcript; it doesn't promise an exact transfer of another system's internal state. Carry says backups stay local and aren't uploaded. A focused first trial is one conversation containing code and an attached file. Inspect what reaches the folder, search for a distinctive line, and open the saved transcript elsewhere. The experiment succeeds when you can recover the part of the discussion you actually needed.

Find DNS records pointing at released cloud addresses

At the infrastructure boundary, Intruder has published a practical investigation of dangling DNS records pointing at released AWS Elastic IP addresses. The researchers report taking over US Treasury subdomains within bug-bounty scope, then reporting the findings and getting them fixed. Their reported cloud cost was about three dollars per valid takeover. The underlying problem is familiar but easy to leave behind during cleanup: a hostname still points at an address the organization no longer controls. If someone else receives that address, traffic intended for the old service can reach them. Cloud maintainers can turn this account into a concrete inventory question. Compare public DNS records with addresses currently allocated to your organization, especially after retiring a service. The researchers' cost and coverage describe their experiment, rather than every environment. A useful improvement is making DNS removal part of releasing an address, with a check that catches the forgotten record before it becomes somebody else's endpoint.
