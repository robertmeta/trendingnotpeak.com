Make enormous workspaces cheaper to start

First up, ABFS makes a fresh Android workspace a much smaller interruption. Google's Android team has open-sourced Another Build File Service, spanning a Linux filesystem module, background services and server infrastructure. It loads files when needed and shares cached source and build results through content-based identifiers. The team reports reducing checkout time from about thirty-six minutes to under eight seconds, and full builds from about eighty minutes to just over two. Those Android results depend on the shared infrastructure and available cached work; they aren't a promise that arbitrary compilation suddenly takes two minutes. The possibility is especially useful for teams creating disposable workspaces for people or coding agents. ABFS lets them reuse Android build work instead of making every new checkout start cold. Its design also targets other massive Git projects. Follow what happens when two workspaces need the same build output, then investigate what changes when one input differs. That's a practical place to begin understanding those dramatic numbers.

Improve an agent by changing one runtime component

Turning to the software around an agent, Harnesses That Improve Themselves studies a controlled way to revise that software while leaving model weights frozen. The framework separates context, control flow, action interfaces and verification. An optimizer diagnoses failures, patches a component, validates the candidate and deploys an accepted update. That gives agent builders something more specific to investigate than asking for a better prompt. A loop breaker, for example, can change what happens when repeated actions stop producing progress. In the reported SWE-bench Lite experiment, gated modular edits reached forty percent accuracy at forty-six point seven thousand tokens per task. A full rewrite reached forty-two point five percent at four hundred fifty-one point six thousand tokens. Those figures come from a small, forty-issue held-out set. The authors also report better cross-model transfer for modular edits. Pick one recurring failure in your own test harness and evaluate a bounded runtime change against untouched tasks. Keep the evaluator outside the editable components.

Explore video generation with shorter feedback loops

Over in moving pictures, Apple's FastFrames release includes two autoregressive video diffusion models that generate four-hundred-eighty-line video in two steps. The smaller model has one point three billion parameters; the larger has fourteen billion. The release also includes an optimized LingBot model for camera-conditioned control. Creative-tool developers can use FastFrames to test interactive video generation, with profiling scripts and a browser-based control demo providing concrete starting points. For the smaller model on one GPU, the published component timings total thirty-five point four milliseconds with a full key-value cache. That timing describes the listed generation components, rather than every part of a complete interactive application. Installation currently specifies Linux and an NVIDIA GPU with a CUDA twelve point eight compatible driver. An Apple release doesn't mean an Apple Silicon runtime is included. For a first experiment, repeat a simple camera movement and measure input-to-visible-response time alongside the consistency of the generated scene.

Build exact CAD geometry through Rust

Heading onto the workbench, springrep is a newly introduced CAD kernel written in Rust. It represents solid boundaries using analytic surfaces and NURBS, the mathematical curves and surfaces used in precise design. Its operations include combining and subtracting solids, rounding edges, sweeping profiles and exporting STEP files. Robotics developers and makers building procedural parts could use springrep to generate exact CAD solids from code. The introductory example creates a plate, cuts a circular opening, rounds an edge and writes a bracket file. Faces retain names tied to the features that created them, giving later operations something meaningful to select. The project says every result is validated, returning an error when a solid fails its checks. Its accuracy and benchmark claims still need independent reproduction. There's an inviting first exercise here: change one bracket dimension, inspect the resulting volume and reopen the STEP export in another CAD application. That connects a short program to a part another tool can examine.

Give model layers persistent companion states

Back inside the model, Latent Lattice Language Models add a persistent companion state to individual layers. Ordinary computation moves through the model's depth. These extra states also travel forward as new tokens arrive, influencing attention, memory writes and other computation. They don't add token positions or extra key-value cache entries. Researchers exploring compact language models get another architectural choice to compare with simply adding parameters or layers. On twenty billion FineWeb-Edu training tokens, the authors report that a four-hundred-six-million-parameter model reduced validation perplexity from fifteen point four one to fourteen point four zero against a parameter-matched Transformer. Lower perplexity means better prediction of held-out text; it doesn't by itself establish better assistant behavior. The paper also reports gains when combining the lattice with other architectural enhancements. A useful reproduction would measure text prediction, generation speed and total state memory together. Persistent state becomes especially interesting when you can see both what it improves and what it costs to maintain.

Bring build and database context into a coding session

Closer to everyday development, GitHub Copilot has added eight service connectors in public preview. These GitHub-verified MCP servers include Buildkite, Supabase and Box, with a connection you can reuse across Copilot clients. The useful change is bringing external project context into the same session where you're working on code. GitHub gives two concrete examples: inspect a failed Buildkite build before fixing the code, or check a Supabase schema before writing a migration. A developer maintaining an application could investigate whether that saves the repeated handoff between a browser, copied logs and an editor. The preview covers all Copilot plans, although business and enterprise access depends on administrator policies, and some services require their own approval settings. Begin with a read-only question whose answer you can check, such as which build step failed. Then compare the connector's result with the original build record. That establishes a useful baseline before combining retrieved context with changes.

Inspect a robot harness built around images and tools

Returning to physical tasks, ORA has released version zero point one of its open robot-use harness. It lets a language model operate through camera images and tools. The project describes using open-weight models without a separately trained vision-language-action model, robot training or task memory. That gives robotics researchers a different integration to investigate: how much useful behavior can come from the surrounding tools and control loop? On DeepSeek V-four point one Flash, the team reports RoboDojo performance increasing from five point two to thirty-nine point nine percent compared with its October preview. RoboTwin rose from seventy-one point five to seventy-nine point six percent. Those are project-reported benchmark comparisons, rather than a guarantee for an unfamiliar robot or task. The Apache-licensed repository includes examples and a run gallery. Follow one recorded attempt from camera observation to tool action, especially where the system needs another look. That can reveal more about the harness than a successful final frame alone.

Make package archives mean the same thing to every tool

At the package boundary, PyPI has explained stricter checks now rejecting some uploaded source and built distributions. The problem is parser disagreement. Two tools can receive identical archive bytes and extract different contents, which means a security scanner might inspect something different from what an installer uses. Even a matching file hash doesn't resolve that disagreement. PyPI's checks aim to make archives conform more closely to their packaging specifications; one documented rejection covers the legacy V-seven tar format. Python package maintainers can use this announcement to investigate release failures and check whether their build tooling produces compliant distributions. The team says package consumers face no breaking implications from these changes. Maintainers seeing failures should use supported Python versions and conforming build backends. For an exercise in your own release pipeline, build a disposable package and inspect both its source archive and wheel metadata. The useful outcome is agreement about what you're actually shipping.

Let a browser baby find the beat

And finally, Baby Plus Music Visualizer gives browser audio analysis a tiny, enthusiastic dance partner. Feed it a local audio file, the microphone or its built-in demo, and a three-dimensional baby chooses dances to match the music's energy. Accessories join the performance. The page also lets you tap the beat, including with the T key, when its tempo estimate needs help. Creative coders could explore that human correction as much as the animation: automatic analysis gets the interaction started, and a simple input lets the listener steer it. The project says everything runs inside the page, microphone sound isn't recorded or sent elsewhere, and the page works offline. Three.js handles the rendering, with web-audio-beat-detector providing a second tempo opinion. Play the demo, tap a different rhythm and watch the response. Your next audio interface might benefit from a similarly obvious way to say, actually, the beat is over here.
