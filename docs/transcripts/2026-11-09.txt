Turn an agent's exploration into reusable procedures

First up, Evolver asks a useful question: why should the next coding agent repeat the exploration the last one already finished? The framework turns execution experience into structured assets called Genes. It collects procedures, retrieves relevant ones before a task, and revises them using feedback, without changing the underlying model's parameters. Researchers evaluated Claude Code and Codex across four benchmarks. On a selected diagnostic set of three hundred twenty paired executions, they report success rising from eighty-three point one three to eighty-seven point five percent, while recorded task-execution tokens fell twenty-four point two four percent. Among the two hundred sixty-five tasks both conditions solved, tokens still fell seventeen point five seven percent. Those are research measurements on a selected set; total costs of maintaining that experience aren't established here. Agent builders could investigate Evolver to reuse agent procedures across recurring tasks. Save a successful troubleshooting route, then check whether it helps on a different failure without dragging yesterday's assumptions into today's code.

Point Docker clients at systemd-nspawn containers

Next up, Nspawn three point zero opens a different container engine to tools that already speak the Docker Engine API. Its new host socket lets those clients manage systemd-nspawn machines. The release account shows the Docker command running containers, executing commands inside them and copying files out. GitLab Runner's Docker executor is a named compatibility target. That gives Linux infrastructure teams a concrete way to investigate another backend without first rewriting every client integration. The socket ships disabled, and access follows the project's existing authorization rules. One detail matters before sharing it: permission to manage machines amounts to root access on the host, because those machines can run privileged commands and mount host paths. API compatibility also needs checking against the operations your tools actually use. Nspawn offers a focused trial: test Docker API workflows with a disposable CI job, then inspect container cleanup, logs and copied artifacts. A familiar client can become a useful probe of a different runtime.

Use hints to forecast beyond near-zero benchmark scores

Over in model evaluation, Hinted Scaling Laws tackles a forecasting problem: small models can all score almost zero on a difficult benchmark, leaving no useful trend to extend. The researchers give those models graduated help, such as partial solutions, and measure how performance changes. They then use that relationship to forecast larger models answering without help. Across GSM-eight-K, AIME and HLE, the authors report median forecasting error falling from twenty-one percentage points to four point three. That's percentage points, which matters when reading the comparison. Model-development teams could investigate this before committing to an expensive training run. The method also offers an evaluation experiment: hints can separate models whose ordinary scores look nearly identical. Check whether that ordering survives when you remove the help.

Explore targeted edits to an open model's output matrix

For a closer look inside open models, Laplace's Scissors introduces an experimental weight-editing tool built around rotating a model's output matrix. The project describes protected readout rotations: calculate corrections for wrong answers while preserving designated successful answers. Its implementation uses Rust and Triton, with CUDA and HIP paths. That gives model researchers something concrete to inspect when studying whether a narrow output repair can leave chosen behaviors intact. The repository's stated protection goal doesn't establish that unrelated generations remain unchanged. An informative experiment would separate the examples you protect from a larger evaluation set the editing procedure never sees. Compare the proposed correction, the protected answers and those untouched prompts. The interesting result would be understanding exactly where the edit's effects spread.

Systemd opens individual components to Rust

Back from the break, systemd has merged support for writing individual binaries in Rust alongside C. Christian Brauner and Lennart Poettering explain a useful architectural boundary: shared core libraries remain C, with Rust wrappers exposing those APIs to Rust components. Rust in the foundational shared library is currently excluded because of shared-library and ABI requirements. Builds stay with Meson rather than adding Cargo as another build system. For systems contributors, this creates a concrete route to using Rust while retaining systemd's existing helpers and conventions. The account also requires consistent option parsing, help and errors across both languages. Maintainers introducing a language into an established project could study those choices, then map which interfaces and build rules their own first component would need to preserve.

Generate a whole visual plan in one pass

Returning to robot planning, VFlash changes how a model produces spatial instructions. A bounding box or trajectory has a known structure, yet ordinary autoregressive generation emits its coordinates one token at a time. VFlash uses a lightweight drafter to predict an entire visual primitive in one forward pass. The researchers report lower prediction errors across evaluated two-dimensional and three-dimensional robot trajectory tasks. A world action model using VFlash plans achieved seventy point two percent average success across four MolmoSpaces task suites, against sixty-two point six percent for the baseline. Robotics researchers could investigate richer plans without paying the same sequential generation cost for every coordinate. The paper also reports preliminary motion-forecasting speed measurements. For a practical comparison, measure plan accuracy and downstream task completion together; a quickly drawn trajectory still has to guide useful movement.

Redox reaches a shell on Cloud Hypervisor

Down at the virtual machine boundary, Redox has merged a Virtio-FS driver and the changes needed to boot to a shell on Cloud Hypervisor. The Rust-based operating system puts drivers, filesystems and its network stack in separate userspace processes. Running as a virtual guest lets developers concentrate on a smaller set of virtual devices while the host handles physical hardware. That's a useful opening for operating-system researchers exploring Redox as a future server platform. Today's milestone is a shell and merged supporting work; the broader cloud-server direction still needs development. The report also discusses Redox hosting virtual machines, explicitly as a proposal. A concrete learning project is following the guest boot path and locating which responsibilities belong to Redox, the virtual machine monitor and the host kernel.

Measure the electricity behind a small Linux builder

For a refreshingly physical infrastructure measurement, Wesley Moore put a Linux package builder on a smart plug. Across a little over seven months, the repurposed Ryzen nine fifty-nine-fifty-X system used ninety-eight point four kilowatt-hours. At his electricity rate, that cost thirty-two Australian dollars forty-seven, excluding the daily service fee. Buildbot recorded five thousand two hundred one package entries, probably inflated by retries. Moore switched the machine off between batches; idle draw was about fifty-five watts. This could help small distribution maintainers think about measuring a home build service. It isn't the project's complete energy bill: packages were first built on another workstation, and Moore estimates actual usage was likely more than double. Borrow the measurement method and include your own idle time, retries and preliminary builds.

A language model takes the SystemVerilog route

And finally, SmolLM in Verilog puts a hundred-thirty-five-million-parameter language model through a SystemVerilog simulator. The tokenizer, thirty decoder layers, attention cache and text decoder live in the same source file. The author reports that two tested next-token outputs agreed with an independent Torch reference, including Paris after a prompt about France's capital. This is behavioral SystemVerilog running through Verilator, using real-number arithmetic, strings and file access. It isn't synthesizable FPGA or chip logic. Hardware-language learners and inference tinkerers can explore the full path from prompt bytes to output text, including a tokenizer-only mode. Patience belongs in the setup: the account estimates roughly twenty seconds per prompt token, so six tokens can mean about two minutes before generated text appears. Even a tiny geography quiz gives this simulator plenty to do.
