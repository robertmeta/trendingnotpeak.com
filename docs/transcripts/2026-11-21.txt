Carry unfinished code between machines

First up, jj-musubi lets unfinished Jujutsu work follow you between computers. Bryan O'Sullivan's new tool synchronizes snapshots, commits and rewritten history through a hub over SSH. Jujutsu already records the working copy as a commit, so a snapshot can travel without inventing a temporary branch to push. Developers who edit on a laptop and build elsewhere could use jj-musubi to sync unfinished changes. Each machine keeps its own working copy; incoming history doesn't replace files underneath a running build. You can also inspect an agent's remote workspace from your laptop, while temporary repositories can lease their membership so vanished machines don't accumulate forever. This is intended for one person using several machines, with that trust relationship defining its security model. There's a pleasantly concrete first experiment: edit on one computer, record a snapshot, and inspect the change on another before deciding to update its files.

Let an agent search quantization recipes

Turning to smaller model representations, QDA asks an agent to design a quantization recipe for a particular model and precision. Quantization stores model values with fewer bits, but preserving useful behavior takes more than choosing a file size. QDA combines compatible methods, builds candidates and evaluates them repeatedly. Its fast screening compares candidate outputs with the original model on reasoning traces hidden from the agent. Promising candidates then generate longer answers to expose failures such as repetition loops. Across four reasoning models, the authors report average gains of zero point nine to two point two percentage points over the strongest public recipes at three tested precision settings, using sixty-four GPU-hours per search. Model-serving researchers could investigate adapting compression to a specific deployment rather than accepting one general recipe. The library, evaluator and harness are promised for release. Until then, the paper offers an inspectable design question: can a cheap screening signal reliably identify which expensive evaluations deserve the compute?

Give a Slack coding task its own computer

Closer to the team chat, OpenComputer introduces an open-source coding agent that works on its own computer. Mention Computer in a Slack thread with a task, and the project describes a workflow where teammates can watch and steer the work before the result arrives as a pull request. You can self-host it in your cloud or use the hosted offering. For a team whose small development requests already begin in chat, that makes the conversation a possible starting interface for implementation. The interesting experiment is whether the agent's separate workspace and visible progress make those requests easier to supervise. The repository carries an Apache license and includes self-hosting documentation. Its description calls it a faster Devin alternative, but there isn't a supported comparative speed result to promise here. Start with a bounded maintenance task whose expected change is easy to review, and see how well the thread preserves the context behind the resulting pull request.

Connect everyday health questions with FAQ answers

For a focused search component, OpenMed has released EmbeddingGemma Two BiomedicalEvidence two-seventy-M version two. The model turns English health questions and answer passages into vectors, so a search system can match ordinary language with relevant medical information. It has two hundred seventy-one million parameters, runs on a CPU and uses an Apache license. Developers building a patient-information library could use OpenMed to search medical FAQs while keeping the retrieval model on their own hardware. The team reports its ranking score improving from eighty-one point six to ninety-one point eight on nineteen hundred sixty-six held-out FAQ questions. That's a retrieval measurement; it doesn't establish diagnostic accuracy. Inputs are limited to five hundred twelve tokens, and questions and passages need the model's specified prefixes. A useful prototype would return the original answer passage with its source clearly visible. Then compare everyday descriptions with clinical terminology and inspect which passages actually rise to the top.

Reduce setup work for local AMD serving

Back from the break, ROCm ten point two brings some useful packaging changes for people serving models on AMD hardware. AMD's builds move to vLLM zero point thirty-two and SGLang zero point five point twenty-one, with both frameworks running on Python three point fourteen. The official vLLM images also include AITER, AMD's optimized AI kernels, for Radeon GPUs and Ryzen AI processors without a separate manual installation. On those platforms, the kernels compile the first time they're used. That distinction matters when you're measuring a fresh launch against a warmed-up server. Developers with compatible hardware get a more direct route into testing a local inference service. The release also expands storage support through hipFile and consolidates Systems Profiler binaries into one command. Rather than assuming every improvement affects your workload, pick one model and record installation effort, first-request time and steady serving behavior. Those observations can tell you whether the refreshed stack removes the particular friction you've been working around.

Help a generated world remember the return trip

Over in interactive video, WorldTrace tackles a wonderfully recognizable failure: you look away, return to a place, and the generated scene has changed. The researchers identify two memory problems. Stored observations become hard to retrieve when their time positions extend beyond the training range, and compressing differently rotated attention keys can damage the summary. WorldTrace assigns compressed memories positions within the familiar range and removes those rotations before merging keys. The model's own attention helps decide which observations stay intact. On LoopBench, the team reports a thirty-two point six percent improvement in average DINOv2 recall similarity over a sliding window with the same cache budget, without retraining the generator. Interactive-world researchers could investigate longer explorations that preserve recognizable places. That score measures visual similarity on a benchmark, rather than proving a physically consistent world. A revealing demonstration would revisit the same room after several different detours and compare which details survive each return.

Bring C sources into an Alice package

Turning to language tooling, Alice zero point six adds building blocks for bringing more OCaml packages into its package format. Packages can now include C source files, which Alice compiles and links into the executable. A configuration script can supply custom C linker arguments, and packages can explicitly request built-in modules such as Unix and Str. OCaml developers exploring this tool can use Alice to build OCaml with C, starting with a small native dependency. The release also adds a bytecode backend alongside the default native backend. The author introduced that partly to compile configuration scripts more quickly, since their output can be cached. These additions support a small collection of manually ported Opam packages; they don't imply automatic compatibility with the whole repository. Follow one small package through its configuration script and linker settings. That's a concrete way to see whether Alice can describe the dependency your project actually needs.

Connect a Raft proof with implementation behavior

At the distributed-systems bench, Antithesis has published a verification account for the designs inside two production Raft libraries, from etcd and HashiCorp. A proof of the original consensus protocol doesn't automatically cover every implementation extension. The team used AI, TLA-plus and trace validation to connect formal models with observed software behavior. Model checking, testing and proof attempts exposed code bugs or gaps in the models, which they then revised. Their final proofs establish core safety properties for the modeled designs after the necessary fixes and workarounds. Distributed-systems engineers get public artifacts to inspect, including models that cover features such as snapshots and leadership transfers. The scope matters: these results concern the features modeled, rather than every possible behavior of either library. The useful possibility is a feedback loop where testing challenges the model and the model challenges the code. Follow one discrepancy through that loop and ask what evidence established that the two finally agreed.

Draw a party-game clue using only triangles

And finally, Polydraw gives the party-game artist sixty seconds and exactly one kind of shape: triangles. Everyone else guesses the prompt. Spritely's new game-jam devlog explains how that small constraint became a peer-to-peer game using Goblins and Hoot. The drawing coordinates are normalized so the same triangles scale across different canvas sizes. Behind the interface, actors represent players, the lobby, the game and each player's controller. The team first simulated a round in one process, then connected the actors across machines using OCapN and an encrypted relay. Game developers curious about distributed applications get a concrete account of that transition under a deadline. It's also a very approachable design exercise: choose a familiar object and see how few triangles make it recognizable. Your drawing may be questionable, but every other player needs to receive the same questionable drawing. That gives the networking a job everyone at the party can understand.
