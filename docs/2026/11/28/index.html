The lead · hottest, not peak#01 ↗

Give agent teamwork an equal-budget test

Story transcript

First up, Recursive Collective Intelligence asks when talking to other agents actually helps. The researchers compare teams with independent agents using the same computation budget. Their toughest comparison counts a problem as solved whenever any independent agent gets it right. Passing that bar requires something useful from the conversation. In their experiments, forwarding facts split across agents puts teams above that comparison at three model scales, by about a third at twenty-seven billion parameters. Identical agents also spontaneously form information-sharing hubs, with a reported eighteen-percentage-point accuracy improvement. Agent builders get a concrete question to investigate: what does each worker know that another worker needs? You could divide a bounded investigation into separate evidence collections, then compare collaboration with independent attempts under the same token budget. The paper also reports successive training gains from groups' own outputs on unseen benchmark problems. These are controlled research results, with an especially practical design lesson: give communication information worth carrying.

Local developer tools#02 ↗

Put personal information tools on one storage contract

Story transcript

Closer to your own files, Pimalaya has released its command-line family together around the first stable pimdir standard. Neverest synchronizes mail, contacts and calendars into one store. Himalaya, Cardamum and Calendula read and search that information, while Carillon watches for changes and fires hooks. Developers building personal dashboards could use Pimalaya to sync mail, then give several small tools access to the same local representation. The coordinated release also standardizes JSON output, errors and exit codes through a shared toolkit. That's useful when a script needs a dependable answer rather than text designed only for a terminal. Existing users should pay attention to migration: the author says these major releases contain breaking changes. A focused experiment would connect a test account, synchronize it, and query one calendar entry and one contact. Then inspect how a requested edit enters the store. The interesting possibility is composing your own interface over information that otherwise lives in separate applications.

AI architecture research#03 ↗

Let repeated model layers share attention memory

Story transcript

Turning inside the model, Mixture-of-Loops Transformer changes what passes between repeated trips through shared layers. Ordinary looping carries the previous pass's internal state forward, creating a dependency that can slow generation. This design lets layers selectively read stored attention keys and values across loops instead. Its U-shaped version separates building that memory from reading it to predict tokens. Model researchers could investigate getting more useful computation from shared weights while avoiding some repeated decoding work. After four hundred billion training tokens, the authors report one point seven times the validation-loss token efficiency of OLMo-three at seven hundred million parameters. Their three-billion-parameter mixture-of-experts model improves ten-task average accuracy by two point one percentage points. The latency comparison needs its own sentence: matching the non-looped baseline was demonstrated at roughly one hundred thirteen million parameters. Code is linked from the paper page. A valuable next test would bring the larger-model quality results and decoding measurements together on the same system.

Local AI experiments#04 ↗

Run a small language model entirely inside a browser

Story transcript

Over in the browser, LLM.OS runs small Qwen models on your CPU through a WebAssembly inference engine compiled from Zig. The engine is about fifty-two kilobytes. The model weights are a separate, much larger download, cached after the first visit. Developers exploring private browser tools could experiment without an inference API or GPU code. The project reports about thirty-nine generated tokens per second for Qwen-three-point-five two-B using eight threads on an Apple M-three Max. That's a measurement on one machine. There's also a Python mode: the model writes code that a separate, networkless WebAssembly Python environment executes for calculations and small charts. The faster inference path rounds activations and can choose different tokens from the more exact implementation. Start with a short question and a calculation whose answer you know. Then compare prompt-reading time with generation time. This experiment makes the browser itself a useful place to study the complete local inference experience.

Why early

Performance and privacy behavior are project descriptions; the faster activation-quantized path can differ from exact inference, and broad browser and hardware behavior remains unestablished.

AI training research#05 ↗

Make verified answers inform a student's token training

Story transcript

Back from the break, Verifiable On-Policy Distillation connects two training signals that don't automatically agree. A verifier can check a completed math answer, but that gives sparse feedback about one attempted response. A teacher model can score every possible next token, although its preferences don't guarantee a correct answer. The new method uses agreement between teacher preferences and verified outcomes to adjust that denser guidance, including guidance for tokens the student didn't sample. Researchers training smaller reasoning models get an implementation to inspect, with code linked from the paper page. Across eight math benchmarks, the reported average for Qwen-three four-B rises from sixty-four point seven one percent under ordinary distillation to sixty-six point three eight percent. The smaller one-point-seven-billion-parameter student also improves in the reported comparison. This still needs sampled attempts and outcome verification. A useful reproduction would record verifier costs alongside accuracy, then inspect whether the extra supervision helps on problems held out from training.

Why early
Recent primary research couples verifier outcomes with dense teacher supervision across two teacher–student configurations and eight mathematical reasoning benchmarks. Code is linked. Results are author-reported; transfer beyond verifiable math tasks and independent compute-adjusted gains remain open.

Follow an inference-tuning experiment on one GB10

Story transcript

Meanwhile, Runtime Notes has published a detailed Inkling two Mini tuning account on one NVIDIA G-B-ten system. The author stayed with vLLM, preserved the model's one-hundred-thirty-one-thousand-seventy-two-token context, and left a second model loaded but idle. The resulting measurements are one hundred one generated tokens per second for one request, and about one hundred ninety-six in aggregate across four concurrent requests. A thirty-two-thousand-token prompt took nine point seven seconds to reach its first generated token. Those figures describe the author's MSI EdgeXpert with one hundred twenty-eight gigabytes of shared memory. Local-serving developers get a concrete request path to study, from prompt processing through speculative drafting and verification to expert computation. The account covers vLLM settings, CUDA graphs and GPU kernels. Follow one adjustment at a time on comparable hardware, recording both first-token delay and sustained generation. A faster stream doesn't automatically mean a faster answer to a long prompt.

Open development environments#08 ↗

Boot a small retro game-development workshop

Story transcript

Down at the workbench, Tiny Hat is a Linux distribution aimed at retro gaming and game development on thirty-two-bit and sixty-four-bit x-eighty-six computers. It includes the Orbiton editor and ways to compile and run C, DOS assembly, Game Boy Advance programs, and LÖVE with Fennel. Learners with an old computer could use Tiny Hat to build retro games in an environment already arranged around that task. Its small footprint is part of the appeal: the project reports eighty-seven megabytes of memory after boot on the thirty-two-bit version, and just over one hundred on the sixty-four-bit version. Disk use is a little above six hundred megabytes. Beneath the retro focus are modern components including Wayland, SDL-three and PipeWire. Some applications in the thirty-two-bit build currently require SSE, which matters on older processors. Open an included example, change one visible behavior, and compile it again. That's a pleasantly direct introduction to making the machine do something of your own.

One for the road#09 ↗

Give a pocket computer exactly one puzzle to run

Story transcript

And finally, Circle with a Line puts a Witness-inspired puzzle game on a pocket-sized Waveshare ESP-thirty-two S-three AMOLED touch board. Steren describes prompting the project from scratch in plain C, including its puzzle generator, vector graphics and synthesized audio, without external game libraries. The screen is the puzzle: drag a line from its starting circle through channels to the exit. Fifty levels across seven chapters introduce rules on small boards before combining them on larger ones. For developers curious about dedicated devices, the inviting possibility is an object that boots directly into something you made. The author describes the board as costing about thirty dollars. The detailed explanation of generation and hardware handling is agent-written, so those internals deserve inspection rather than automatic trust. If you already have the supported board, follow the build instructions and change one puzzle rule. Your weekend project could become a little machine whose entire purpose is giving somebody one satisfying problem.
